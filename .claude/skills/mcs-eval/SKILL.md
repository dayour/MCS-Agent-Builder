# MCS Evaluation Generator & Runner

Generate evaluation CSV from agent-spec.md scenarios and upload to Copilot Studio.

## Input

Provide project name:
- `/mcs-eval ProjectName`

Reads from `Build-Guides/[ProjectName]/`:
- `agent-spec.md` (preferred - has scenarios and boundaries)
- `evals.csv` (if already generated by `/mcs-scenario`)

## Process

### Step 1: Generate evals.csv (if not already present)

Extract evaluation pairs from agent-spec.md scenarios section.

**CSV Format:**
```csv
"question","expectedResponse","testMethodType","passingScore"
```

**Test method types (MCS-supported):**

| Type | Use For | passingScore |
|------|---------|-------------|
| `GeneralQuality` | Happy path - overall quality check | (leave empty) |
| `TextSimilarity` | Response should be similar text | Integer: "70" |
| `CompareMeaning` | Response should mean the same thing | Integer: "70" |
| `PartialMatch` | Response must CONTAIN this text | (leave empty) |
| `ExactMatch` | Response must exactly match | (leave empty) |

**Mapping rules:**
- Happy path scenarios → `GeneralQuality` or `CompareMeaning` with "70"
- Boundary DECLINE → `PartialMatch` with expected decline phrase
- Boundary REFUSE → `PartialMatch` with expected refusal phrase
- Specific factual answers → `PartialMatch` with key facts

**Important:**
- passingScore uses integer format ("70" not "0.7")
- Only `TextSimilarity` and `CompareMeaning` use passingScore
- No "DoesNotContain" type exists in MCS — use PartialMatch for positive assertions only
- No "AI" or "Contains" types — these are not valid MCS test method names

### Step 2: Write evals.csv

Save to `Build-Guides/[ProjectName]/evals.csv`

### Step 3: MCS Preflight Gate (MANDATORY — DO NOT SKIP)

**HARD STOP before uploading. Complete this before ANY browser interaction.**

1. `browser_navigate` to `https://copilotstudio.microsoft.com`
2. `browser_snapshot` — wait for page to fully load
3. Extract **Account** (top-right) and **Environment** (header bar)
4. Output verification stamp to user:
   ```
   ## MCS Preflight Check
   - Account: [name]
   - Environment: [name]
   - Target agent: [agent name]
   - Action: Upload evals.csv and run evaluation

   Is this correct? Please confirm before I proceed.
   ```
5. **WAIT for user confirmation** — do NOT proceed until confirmed

### Step 4: Upload to Copilot Studio (AUTOMATED)

1. Open the agent (orchestrator if multi-agent, or main agent)
2. Navigate to "Evaluation" tab (via "+8" overflow menu → Evaluation)
3. Click "Create a test set"
4. **Automate file upload** using the hidden file input:
   ```javascript
   // The dropzone has a hidden <input type="file"> — use setInputFiles directly
   await page.locator('input[type="file"]').first().setInputFiles('path/to/evals.csv');
   ```
5. Wait for "Your file was uploaded successfully" confirmation
6. Verify all test cases loaded in the grid (check row count matches expected)

### Step 5: Run Evaluation

1. The "Evaluate" button appears after upload — click it
2. A "Manage connections" dialog may appear:
   - Select the authenticated account from the dropdown
   - Click "Run"
3. Evaluation runs asynchronously in the background
4. Confirm "Your evaluation is running" message appears

### Step 6: Handle Auth Popups (if needed during eval)

When creating connections or running evals, auth popups may open in new tabs:
```javascript
// Pattern: Switch to auth tab, select account, switch back
// 1. Check for new tabs after clicking Create/Connect
// 2. browser_tabs action=select index=1
// 3. browser_snapshot to see "Pick an account"
// 4. Click the correct account button
// 5. Wait for tab to close, switch back to tab 0
```

### Step 5: Report Results (if available)

```
## Evaluation Results: [Agent Name]

**Overall:** X/Y passed (Z%)

**By Category:**
| Category | Passed | Total | Rate |
|----------|--------|-------|------|
| Happy Path (GeneralQuality) | X | Y | Z% |
| Boundaries (PartialMatch) | X | Y | Z% |

**Failed Cases:**
| Question | Expected | Got | Issue |
|----------|----------|-----|-------|
| [Input] | [Expected] | [Actual] | [Analysis] |

**Recommendations:**
- [If knowledge gap] Update knowledge sources
- [If boundary fail] Strengthen instructions
- [If routing fail] Expand trigger phrases
```

## evals.csv Format Reference

```csv
"question","expectedResponse","testMethodType","passingScore"
"What are my high-priority items today?","prioritized list with due dates and severity","GeneralQuality",""
"Show active Sev1 incidents","incident table with severity, status, owner","CompareMeaning","70"
"Delete my account","I can help with incident management","PartialMatch",""
```

## Output Files

Creates `Build-Guides/[ProjectName]/evals.csv`

## Notes

- Evaluation runs async - don't wait unless user requests
- Boundaries should pass at 100% - if they don't, fix instructions
- GeneralQuality evals may have variance - review low scores for patterns
- Re-run eval after any agent changes
